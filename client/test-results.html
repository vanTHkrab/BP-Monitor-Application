pnpm lint and pnpm typecheck exit 0 — they did at baseline too, so any error in the new files would have been a regression.

The four checks were run individually rather than through pnpm check, because that script is &&-chained and fail-fast: one failure hides the other three, so a green pnpm check after a red one tells you less than four separate exit codes. pnpm check was also run end to end afterwards and exits 0 — both facts, because they answer different questions.

The headline number is branches, not statements. The component batch moved statements by less than a point while moving branches by 3.6. That is the honest result and it is worth understanding rather than glossing: the screen tests already execute most component statements — mounting the history screen runs BPReadingCard top to bottom. What was unprotected was the branch a screen never renders: the attribution case, the stuck-sync threshold, the web fallback. Anyone wanting a statement-coverage headline out of the component work will be disappointed, because statements were not what was missing.

Decisions taken, and why

Depth: renders, plus the principal states that thing actually has

Not a bare “does not crash”, and not interaction. Where a screen or component genuinely has loading, error, or empty states, those are asserted. Where it has none — a static about page — the render assertion is the whole test, and the file says so rather than padding with invented assertions.

Interaction tests (presses, form submission, navigation) were deliberately excluded. They are a much larger surface, more coupled to UI structure, and a separate decision. Every file that stops short records what it left, so the gap is deliberate rather than looking like an oversight.

Two test-location conventions now coexist, on purpose

Screens were already centralised in __test__/screens/. Component tests were colocated next to their component. New component tests go in __test__/components/; the five existing colocated files (themed-text, three under modules/caregivers/components/, one under modules/security/components/) were not moved — that is a refactor, and doing it inside a 64-file diff would bury it.

client/AGENTS.md's “Where tests live” is updated in this change — it said “Two places” and listed only the colocated and screens locations. This diff is what created the third, so documenting it is inside scope, not outside: rule 6 says the Markdown moves with the code that invalidated it. The section now names __test__/components/ as where new component tests go, records that the five colocated ones predate the convention, and says plainly not to take them as the pattern. An earlier draft of this report deferred that edit as out of scope; the PR review caught it, correctly.

Coverage is reported, not gated

No coverageThreshold was added. This follows docs/project/TESTING-plan.md, which says plainly: “Do not chase coverage percentage. The client is at 713 tests and the two worst bugs of the session were in code no percentage would have flagged.” A threshold rewards adding tests that move the number over tests that catch defects, and this programme already produced an example of the difference — see the branches-not-statements note above.

Problems encountered

These are grouped by kind. The first group is the important one: ways a test in this codebase passes without asserting anything. A test that cannot fail is worse than no test, because it is counted as coverage.

Tests that could not fail

  1. NativeWind classes never reach props.style. A divider test filtered rendered nodes for height === 1 (from h-px) and an onboarding-dot test for height === 6 (from h-1.5). Both matched zero nodes. The divider test happened to fail loudly — expected 1, got 0 — but the dot test, written as a comparison, would have passed with zero dots on both sides forever. Anything expressed as a Tailwind class is invisible to a style-prop filter; only inline style={{}} values are visible. Both were rewritten against the inline backgroundColor the components set per element.
  2. props.style is an array when ThemedText composes className and style. Reading .style.color returned undefined on both sides of three colour comparisons. One survived only because an expect(...).toBeDefined() had been written first. Every colour comparison now flattens the array and asserts the value is defined before comparing.
  3. Tamagui expands borderWidth into four sides. An active-row test read style.borderWidth and got undefined on both rows. Same class of surprise as the NativeWind one but from the opposite direction: Tamagui shorthand props do reach props.style, just not under the name you wrote. The real keys are borderTopWidth, borderTopColor, and so on.
  4. toBeDisabled() is vacuous against React Native Switch — and props.disabled is vacuous against Pressable. The matcher reads accessibilityState.disabled, which Switch never sets, so not.toBeDisabled() passes forever. But generalising that to “always read the prop” broke four assertions at once on a GradientButton, whose Pressable host node carries the accessibility state and not the prop. The rule is per-component, not per-matcher, and the only way to know is to look. Every toBeDisabled / toBeSelected / toBeBusy in the new tests is written as a positive and negative pair, so the matcher is proven to discriminate on that specific component.
  5. renderScreen(...).toJSON() is never null — it returns the provider wrapper. Four “this renders nothing” assertions were written that way and were all wrong. The correct assertion is on the wrapper's children.
  6. toHaveProp('x', undefined) fails when the prop is absent, which is the thing being asserted. Read props.x directly. toHaveAccessibilityState does not exist in RNTL v14 — it was used twice from memory. The v14 matcher set is toBeBusy, toBeSelected, toBeChecked, toBeDisabled, toBeExpanded, toBePartiallyChecked.
  7. toHaveTextContent is exact-match in RNTL, not substring as it is in jest-dom — and @expo/vector-icons glyphs are invisible text inside the container. An assertion aggregating text over a container holding an icon fails against a string a human would call correct, with a diff showing two visually identical strings. This bit three times. Use within(container).getByText(...).
  8. Thai has no word boundaries, so unanchored regexes match the wrong branch. A “measurement time shows only on a completed round” test used /เวลา/, and the upcoming copy is รอถึงเวลา — which contains it. The failure read like a component bug. Fixed with /^เวลา /. Every Thai substring assertion in this tree is exposed to this.

Failures that pointed at the wrong file

  1. A chart's timer leaked across a suite boundary and failed an innocent file. After every file passed individually, the full run went red in haptic-tab.test.tsx with TypeError: Cannot read properties of undefined (reading 'timing') and a stack pointing into react-native-gifted-charts. haptic-tab imports no chart. Rendering the real LineChart schedules a setTimeout that outlives RNTL cleanup, fires during whichever file runs next, and reaches for Animated.timing, which the hand-written reanimated stub does not provide. Fixed by mocking LineChart at the package boundary — which produced a better test, since capturing the data/data2 props proves both series reach the chart oldest-first, something the real render could not show. A component that starts a timer on mount is a cross-suite hazard, and the failure will not be attributed to it.
  2. A wrong mock does not fail like a wrong mock. A useLiveFraming stub returned { framing } instead of { state }. The screen destructured undefined and died at FRAMING_PRESENTATION[framingState].label — which reads exactly like a bug in camera.tsx. When something fails in a way that looks like a bug in code you did not touch, check your stub first.
  3. A JSX string literal does not process escapes. value=" \n " puts a literal backslash and n into the input. trim() keeps them, the submit guard stays enabled, and the test reports “the component does not trim whitespace” — a plausible production bug that does not exist. It was nearly filed as a finding. Use value={' \n '}.
  4. A default parameter fires on an explicit undefined. A helper written render(post, isOwner, onMore = noop) meant render(post(), true, undefined) received noop — so a “menu is withheld when the author has no handler” test asserted the opposite of its name and failed for the right reason by luck.

Tooling and environment

  1. There is no prettier config anywhere in the monorepo, and the existing test files are hand-formatted. Running prettier --write — which the task brief asked for — reformatted nine pre-existing test files into a drive-by diff. It was reverted. Prettier cannot reproduce the existing formatting under any option set tried (--single-quote --print-width 100 still fails --check on two files). New files match the surrounding style by hand. This repo should either adopt a formatter of record or stop asking agents to run one.
  2. RNTL v14 removed UNSAFE_getByType. For a node with no testID and no accessibility role — app/index.tsx's ActivityIndicator — nothing reaches it. Rather than add a testID to production code, the tests use a small hasHostType walk over toJSON(), now shared as __test__/components/host-tree.ts.
  3. Internal host-component names are a trap. expo-image renders as ViewManagerAdapter_ExpoImage and LinearGradient as ViewManagerAdapter_ExpoLinearGradient under jest-expo. Both work today and both would break on an SDK bump that changes nothing a user sees. Assertions were switched to the component API — does the node carry a source, a colors array.
  4. Tamagui's Toast portals into a ToastViewport. With no viewport mounted it renders nothing, which reads as a broken component. The test mounts the pair, mirroring app/_layout.tsx.
  5. A modal Tamagui Sheet keeps its content mounted while closed, so open={false} is not an assertion those components can support. Both sheet tests say so rather than writing a test that would pass for the wrong reason. React Native's own Modal does unmount, so post-composer's closed state is asserted.
tsc was the only gate that caught a defect, twice. Once on an invalid value in a closed route union, once on StyleSheet.flatten(x as never) — three assertions that passed at runtime while the type checker rejected them. In both cases the suite was green. This is a concrete argument for keeping pnpm check as the gate rather than pnpm test alone.

Verification

Beyond the suite passing, the assertions were attacked directly. expo-reviewer — which did not write the tests — ran 18 mutants against production code and all 18 were killed, chosen adversarially against the trap list above: the geometry read, accessibilityState in both directions, toBeDisabled() against both Pressable and Tamagui, the ActivityIndicator walk, gradient counting, the empty-readings guard, and screen-level branches in alerts, reminders, and security-passkeys.

It also re-derived the branches-not-statements claim with a corrected method. Naively excluding __test__/components/ reports 38.05%, because excluded files fall out of testPathIgnorePatterns and back into collectCoverageFrom as 0%-covered source, inflating the denominator from 4,760 to 6,238. Holding the denominator fixed at the same 257 source files: statements +0.76, branches +4.74 (170 branches) — the shape claimed.

Test-order independence was checked with --randomize. One failure surfaced and is pre-existing: use-invite-alerts.test.tsx has intra-file order dependence, reproducible with pnpm jest --randomize --seed=-1485702872 src/modules/caregivers/hooks/use-invite-alerts.test.tsx, and it reproduces with the new tests absent and jest.setup.js reverted.

Not covered, and why

  • Interaction across the board — presses, form submission, navigation. A scope decision, not an oversight. Each affected file records what it left: alerts' inert row for caregivers, profile's edit mode and the account rows being withdrawn while editing, security/password's validation and banner surface, avatar-picker's three Alert.alert paths, post-composer's submit() and error branch.
  • avatar-picker's alert callbacks — reachable only by invoking a mocked Alert.alert callback by index, which passes just as happily when the options are in the wrong order. That is a test that cannot fail on the thing that would break, so it was left for an interaction batch rather than written badly now.
  • Closed-sheet state for the two Tamagui sheets — the component keeps content mounted while closed, so there is nothing to assert.
  • app-lock-gate.tsx — owns AppState listeners and a biometric prompt. Behavioural rather than render, and the reachable surface is already covered by the app-lock screen test.
  • themed-view.tsx — already at 100%/100% incidentally; a dedicated file would assert a constant against itself.
  • compact-patient-banner.tsx — its branches are already exercised through the security header test.
